# RoR2 level caps: implementation precedents and release notes

## What existing mods actually change

| Released mod | What its shipped code does | Implication for this mod |
| --- | --- | --- |
| [Roflers / RemoveMonsterLevelCap 1.0.0](https://thunderstore.io/c/riskofrain2/p/Roflers/RemoveMonsterLevelCap/) | When enabled (default), handles `Run.onRunSetRuleBookGlobal` and assigns `int.MaxValue` to `Run.ambientLevelCap`. [Decompiled DLL](https://old.thunderstore.io/c/riskofrain2/p/Roflers/RemoveMonsterLevelCap/source/) | This is an ambient monster cap change. It does not extend the player XP table. |
| [ZetaArcade / CustomMonsterLevelCap 1.0.0](https://thunderstore.io/c/riskofrain2/p/ZetaArcade/CustomMonsterLevelCap/) | `Update()` reasserts a positive configured `Run.ambientLevelCap` whenever it differs. The default is **99**. [Decompiled DLL](https://old.thunderstore.io/c/riskofrain2/p/ZetaArcade/CustomMonsterLevelCap/source/) | With both mods installed, even the default config can undo another mod’s one-time change on the next frame. |
| [gameimprovement / LevelCaps 1.1.1](https://thunderstore.io/c/riskofrain2/p/gameimprovement/LevelCaps/) | Replaces `TeamManager.levelToExperienceTable`, `naturalLevelCap`, `hardExpCap` and `Run.ambientLevelCap`; patches `SetTeamExperience` to apply a separate player limit. Its table changes the XP curve above level 30 by default and budgets remaining `ulong` range across remaining levels. [Decompiled DLL, `Apply` and `BuildTable`](https://old.thunderstore.io/c/riskofrain2/p/gameimprovement/LevelCaps/source/) | Raising the ambient cap and changing XP-derived levels are separate operations. This mod also changes difficulty and combat, so it is a poor control for testing vanilla progression. Its author recommends matching installs/settings on all peers. |

These are observations of those releases, not proof of current game behavior. For a runtime check, [DebugToolkit](https://thunderstore.io/c/riskofrain2/p/IHarbHD/DebugToolkit/) documents two separate controls: `run_set_stages_cleared {stage_count}` changes the stage count without advancing the scene; `team_set_level {team} {level}` sets a team level. Test ambient scaling and XP-derived progression separately; a forced level alone does not demonstrate XP awards crossing a boundary. [Author’s command reference](https://github.com/harbingerofme/DebugToolkit/blob/4d4bbc302cd48f7c021304153a1ecf9abcce8e07/README.md#unlocked-vanilla-commands)

**Moffein’s successor:** The [deprecated Raise Monster Level Cap listing](https://thunderstore.io/c/riskofrain2/p/Moffein/Raise_Monster_Level_Cap/) directs users to [Risky_Lives / RiskyTweaks](https://thunderstore.io/c/riskofrain2/p/Risky_Lives/RiskyTweaks/#enemy-mechanics). In 1.11.2, `[Enemies]` → `(Server-Side) Raise Level Cap` is [enabled by default](https://github.com/Moffein/RiskyTweaks/blob/b08bc13fd6090b7e39068a7c9dda8a361cf344d4/RiskyTweaks/Tweaks/TweakBase.cs#L30-L39); its `- Max Level` setting defaults to **9999** for ambient monster scaling, not player XP. The [tweak](https://github.com/Moffein/RiskyTweaks/blob/b08bc13fd6090b7e39068a7c9dda8a361cf344d4/RiskyTweaks/Tweaks/Enemies/RaiseLevelCap.cs) makes the difficulty calculation read that setting instead of `Run.ambientLevelCap`. Disable it when testing a mod that only writes that field.

## BepInEx and Thunderstore conventions

- The [Risk of Thunder example project](https://github.com/risk-of-thunder/ExamplePlugin/blob/bb5d7d0e867cee468adc6ea262adb7e33502beab/ExamplePlugin/ExamplePlugin.csproj) targets `netstandard2.1`. BepInEx loads the plugin; HookGenPatcher generates `MMHOOK_RoR2` for `On.`/`IL.` hooks. Declare the runtime dependencies actually used; the tutorial’s R2API Items/Language modules serve its example item. If using an `On` hook, call `orig` to preserve the hook chain. [First Mod](https://risk-of-thunder.github.io/R2Wiki/Mod-Creation/Getting-Started/First-Mod/) · [Hooking](https://risk-of-thunder.github.io/R2Wiki/Mod-Creation/C%23-Programming/Hooking/)
- Put `manifest.json`, UTF-8 `README.md`, and exactly 256×256 `icon.png` **at the ZIP root**, names case-sensitive. `CHANGELOG.md` is optional. The manifest needs `name` (ASCII letters, digits, underscores), `version_number` (`Major.Minor.Patch`), `description` (≤250 characters), `website_url` (empty string allowed), and `dependencies` (`Team-Package-Version` strings). Put the plugin DLL under `plugins/` or `BepInEx/plugins/`. Do not ship game DLLs absent explicit developer permission. [Package format](https://wiki.thunderstore.io/mods/creating-a-package) · [Loader paths](https://wiki.thunderstore.io/mods/packaging-your-mods) · [Global rules](https://wiki.thunderstore.io/moderation/global-rules)
- Import the **release ZIP** into a clean mod-manager profile, launch the game, exercise the feature and check logs before upload. RoR2’s `Client-side` and `Server-side` categories describe installation requirements; the tags do not enforce networking behavior. Verify host and remote-client observations before claiming host-only support. [First upload](https://wiki.thunderstore.io/mods/your-first-upload) · [RoR2 networking guidance](https://risk-of-thunder.github.io/R2Wiki/Mod-Creation/C%23-Programming/Networking/Server-side-and-client-side-mods/)

## AI use: what to disclose when publishing

- **Platform-wide:** Generated **assets or code** should receive the `AI Generated` category wherever available. The [Global Rules](https://wiki.thunderstore.io/moderation/global-rules#ai-generated-content) say this is “generally not enforced for READMEs or icons”; that is an enforcement qualifier, not a blanket exemption. Untested or nonfunctional AI-generated mods are explicitly prohibited as spam. The README should describe functionality the submitted version actually has.
- **RoR2 specifically:** The [current community banner](https://thunderstore.io/c/riskofrain2/) says, “Add the `AI Generated` category to your mod if it was made with AI tools. Failure to do so may result in the mod being removed from Thunderstore.” The [legacy community page](https://old.thunderstore.io/c/riskofrain2/) says “any significant portion” without defining a threshold. For AI-generated plugin code, select **Risk of Rain 2 → AI Generated** on upload. Categories are listing metadata, chosen after the community, not a `manifest.json` field. [Upload instructions](https://wiki.thunderstore.io/mods/your-first-upload#upload)
- **README and assembly disclosure:** Thunderstore’s separate official [LLMs and AI-generated files](https://wiki.thunderstore.io/llms-and-ai-generated-files) page says to disclose AI use in the README if it was used to create the mod or package; for generated code, identify the LLM or agent in **both the README and `.csproj` `AssemblyMetadata`**. Its example uses `AI_Assisted_Creation` and `AI_Model_Vendor`; the text asks *which* LLM/agent, so include its actual name. This guidance is separate from the global moderation rules; neither page says disclosure substitutes for the RoR2 category.
- **Icon-only edge case:** The [first-upload guide](https://wiki.thunderstore.io/mods/your-first-upload#your-icon) says many users *prefer* non-AI icons. The cited public rules do not state a blanket ban on AI icons or AI-authored mods. They also do not settle whether an icon alone is a “significant portion” for RoR2. For an icon-only submission, disclose its origin and ask [RoR2 moderators](https://discord.gg/5MbXZvd) if category treatment matters. For this project, generated code already resolves the category question independently of the icon.
